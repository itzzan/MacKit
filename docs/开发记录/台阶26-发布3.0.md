## 你要做的事：做一张"MacKit"证书，并备份（大约 5 分钟）

证书是你钥匙串里的东西，我不碰，这几步要你自己点。做好以后告诉我"证书做好了"。

1. 打开"钥匙串访问"（按 ⌘空格 搜"钥匙串访问"）
2. 菜单栏"钥匙串访问 → 证书助理 → 创建证书…"
3. 填：
   - 名称：**MacKit**
   - 身份类型：**自签名根证书**
   - 证书类型：**代码签名**
   - 勾上"**让我覆盖默认值**"（要改有效期，第 1 条拍板），点"创建"→ 弹出的提示点"继续"
4. 有效期（天数）：填 **3650**（10 年），继续
5. "证书信息"那一页：**电子邮件地址那一格清空**；名称是 MacKit；单位、部门、城市、省份都**空着**（这张证书会跟着安装包公开，里面不要有你的名字和邮箱）；国家或地区随便。继续
6. 后面几页（密钥大小、密钥用途、扩展密钥用途……）都不用改，一路"继续"；最后"钥匙串"选**登录**，点"创建"，完成
7. 备份：在"钥匙串访问"左边点"我的证书"，右键"MacKit"→"导出'MacKit'…"，格式选"个人信息交换（.p12）"，**存到项目文件夹以外的地方**（比如 iCloud 云盘、U 盘），设一个密码，记在你的密码管理器里
   - 这个 .p12 文件千万别放进 MacKit 项目文件夹，也别发给别人：拿到它的人能签出"系统认为是 MacKit"的软件
   - 换电脑时，双击这个 .p12、输密码，就装回去了

之后第一次用它签名时，系统会弹窗问"codesign 想要使用钥匙串中的密钥'MacKit'签名"，你输登录密码，点"**始终允许**"。

## 技术要点（备忘）

- release.sh：签名用"MacKit"证书（环境变量能换别的名字）；先把原来的签名整个去掉再签（和现在一样，免得旧签名里的名字、团队编号残留）；找不到证书就停下说明，不偷偷退回临时签名
- 发布前检查（有一样不对就停）：签名的证书只有"MacKit"一张；没有团队编号；把签名里的证书取出来看，主题只有"MacKit"（国家可以有），没有邮箱、单位、名字；原来那些检查照旧（包里没有你的团队编号、开发证书名字、邮箱）
- 系统记权限时记的是"签名要求"：现在是"标识 local.mackit.MacKit + 用这一张证书签的"。测试版 3.0.1：改个版本号另打一个包（不发布、不进 git），用系统的签名检查（codesign --verify -R）拿 3.0.0 的签名要求去验 3.0.1，过了就说明系统会认成同一个软件
- 自签证书在系统看来"不受信任"：不影响，权限认的是签名要求，不看信任；万一 codesign 因为不受信任不肯签，就在钥匙串里把这张证书的"代码签名"设成"始终信任"（你来改，要输一次登录密码）
- 证书丢了、过期了：用新证书签的那一版，别人要重给一次权限——所以 10 年 + 备份
- .gitignore 加上 *.p12、*.cer，防手滑把证书放进仓库
- 私钥只在你的钥匙串里：我不导出、不复制、不读，只用 codesign 签名（每次签都要你钥匙串点过"始终允许"）
- 老用户提示：上次打开的是 2.x、这次是 3.x 才弹一次；3.0 → 3.0.1 不弹；新用户不弹；自检里测这几种，自检本身不弹
- README：能干什么补第三版；常见问题"更新到新版本后截图不行了"改成"3.0 以后更新不用重给；从 2.x 或更早升到 3.0 要最后重给一次"；图用 MacKit 自己的画图命令重画
- 版本号 3.0.0（build 31），标签 v3.0.0；更新说明草稿放 build/发布说明-3.0.0.md（不进 git）；按功能分组挑重点，最后一段"从 2.x 升级"
- 发布前照旧查：安装包、README、更新说明里没有团队编号、证书上你的名字、邮箱
- 发布后用 GitHub 公开接口读 v3.0.0 那一版的附件核对，不用登录、不发任何东西
